## Key results from the included runs
* Q1: D&C Max/Min matches ceil(3n/2)-2 for powers of two (e.g. n=1024: 1534 vs 2046 for two scans); for other n the observed count is higher (n=100: 162 vs 148) due to uneven splits. Binary search never exceeded floor(log2 n)+1 probes (n=10^6: <= 20).
* Q2 (n=1023): balanced Quick Sort depth 10, 8,194 comparisons; sorted input depth 1023, 522,753 comparisons; Merge Sort 5,110 comparisons, depth 11 on any input. Depth grows as log n / log(1/r) for an r:(1-r) split.
* Q3: digit multiplications n^2 vs ~n^1.585 (n=2048: 4.19M vs 345k). Karatsuba is slower in time below ~256-512 digits in this pure-Python implementation; hybrid cutoff ~16 digits was fastest at n=1024.
* Q4: Strassen uses fewer multiplications (n=128: 823,543 vs 2,097,152) but many more additions and was slower in every timed case here (pure Python 25x at n=128 with cutoff 1; NumPy ~3x slower than BLAS). Padding can add up to ~290% extra cells (n=129 -> 256).
* Q5: D&C distance computations ~ n log n (n=4000: 4,637 vs 7,998,000); practical time crossover ~ n=20-30 in this implementation.
* Q6A: deterministic first-element pivot on sorted input: 1,501,500 comparisons (n=2000) vs 11,290 for Median of Medians (but MoM costs ~8n comparisons on random data, more than QuickSelect's ~3-4n). Q6B: n=40: 2^40 subsets vs 2,097,152 sums generated.
